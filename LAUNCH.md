## Hacker News (Show HN)

**Title:** Show HN: MCP tool linter – score your tool schemas for LLM-callability

**Body:**

A common complaint in the MCP world: the schema validates, the server runs, and the model still calls the wrong tool. The causes are never crashes — they're descriptions that are 12 characters long, two tools named `read_file` and `read_file_v2`, a `mode` param typed as a bare string, a destructive tool with no `destructiveHint`. None of that fails a JSON Schema validator.

So I wrote a linter with 24 rules across five dimensions — describing, schema, ambiguity, safety, ergonomics — scored 0–100 by additive deduction, with the specific fix printed next to each finding. Example, verbatim lines from `mcp-tool-lint fixtures/raw/filesystem.json` (the ↳ fix lines are elided here):

```
     19.0  read_file                     ██░░░░░░░░░░  F
          error  desc/too-short             Description is only 12 chars ("Read a file.") — too short to distinguish from sibling tools.
          error  ambiguity/name-collision   `read_file` and `read_file_v2` are 75% confusable — same verb, overlapping object.
          warn   desc/params-undocumented   None of the required params (path) appear in the description.
```

The part worth arguing about is the collision detector. The obvious approach is string similarity — and it gives you no usable line in the sand:

```
read_text_file / read_file_bytes   trigrams 0.44   <- model WILL confuse these
list_tables    / list_views        trigrams 0.38   <- nobody confuses these
```

Those two pairs are 0.06 apart. Token overlap is worse: `delete_path` / `delete_file` (confusable) and `list_tables` / `list_views` (distinct) both score 0.33. What actually matters is same-verb + near-synonym object, so that's what it keys on — with one refinement: when two names share only a head noun and differ by action verbs (`run_select_query` vs `run_write_query`), the modifier names the operation and the pair is separable (0.50, not flagged).

To keep myself honest the repo ships three API pairs, each written twice: as people actually write servers, and fixed. From this repo's paired fixtures: raw averages 37.9, polished 97.1, gap +59.2 — and the benchmark fails CI if that ordering breaks, if polished drops below 70, or if the polished set has any error-level finding.

Honest limits: it's lexical heuristics, English-only, and the score is a hypothesis about model behaviour — no model was queried. It shows separation, not validity. The obvious next experiment is routing prompts + a real model + correlation against score.

`npx @llz-real/mcp-tool-lint fixtures/` (scoped name — the unscoped one belongs to a different project; on npm after publish).

## Reddit r/mcp

**Title:** I built a linter for MCP tool schemas — and shipped the bad fixtures it was written to catch

**Body:**

Most MCP tooling validates structure. Almost nothing checks whether a model can *route* to the right tool and *fill* it correctly — which is where the real failures live: a 12-char description, `read_file` next to `read_file_v2`, `mode: string` with no enum, a destructive tool with no `destructiveHint`.

mcp-tool-lint: 24 rules, 5 dimensions (describing, schema, ambiguity, safety, ergonomics), 0–100 by additive deduction, with the fix printed next to each finding. CLI, JSON, and Markdown output; `--fail-under` for CI; can probe a live server over real MCP stdio or read saved fixtures.

To keep it honest the repo ships three APIs written twice — raw (as people write them) and polished (fixed). The linter has to separate them, and the benchmark fails if it stops:

| | raw | polished |
|---|---:|---:|
| filesystem | 38.4 F | 99.3 A |
| web-fetch | 28.5 F | 100.0 A |
| database | 46.8 F | 92.0 A |

(From this repo's paired fixtures; `npm run bench` regenerates the numbers.)

On the deliberately-bad raw fixtures the top findings are what you'd guess: `schema/param-undescribed` (24 hits), `schema/unbounded-string` (17), `safety/no-annotations` (16), `desc/no-return` (16), `desc/too-short` (14).

The one I did not expect: **`list_tables` vs `list_views` are not confusable (0.50), but `delete_path` vs `delete_file` are (0.75).** Word overlap can't tell the difference — it needs a notion of near-synonym. That's now the core of the collision rule.
